# API Reference

## Telemetry RPC

The kit verifies a token at each gate checkpoint via a Supabase RPC:

```text
verify_kit_token(p_token, p_kit_version, p_checkpoint)   -- 3 params
```

> Always call the **3-param** form. A 2-param overload causes an RPC ambiguity error.

- `KIT_VERSION` is read dynamically from `PROMPT_VERSION` in
  `commands/feature-from-confluence.md` — never hardcoded.
- On success, telemetry inserts into `usage_logs` and upserts `repo_runs` (so the
  dashboard knows which repo ran which version).
- Checkpoints: `step0`, `B0`, `B5`, `B11`, `B12`.

## Supabase schema (dashboard)

| Table | Key columns |
|-------|-------------|
| `usage_logs` | `created_at`, `token_id`, `checkpoint`, `kit_version`, `event_type` (`verify` / `feature_built` / `admin_bypass`), `is_anonymous`, `feature_name` |
| `tokens` | `id`, `owner_name`, `owner_email`, `status`, `runs_used`, `max_runs`, `expires_at`, `token_prefix` |
| `error_reports` | `id`, `error_type`, `message`, `kit_version`, `phase`, `created_at`, `token_id` |
| `admin_bypass` | `id`, `label`, `bypass_code_hash`, `bypass_code_prefix`, `status`, `uses`, `expires_at` |
| `installs` | `repo` (PK), `kit_version`, `synced_at` — version synced onto each repo |
| `repo_runs` | `repo` (PK), `last_run_version`, `last_run_at` — version each repo last ran |
| `command_runs` | per-run metrics (status, duration, exit code, log tail) — Command Runner |
| `token_usage` | per-run token in/out, cache, cost estimate, model — Command Runner |

## Sync

The kit is the source of truth and pushes one-way into target repos:

```bash
npm run sync        # copy allowlist paths → targets, report install version
npm run sync:dry    # preview, write nothing
npm run sync:rollback -- --target ../isu-elearner-learning   # undo the last sync
```

- `sync.config.json` declares `targets` + `syncPaths` (allowlist:
  `commands/`, `integrations/`, `templates/`, `_content/`, `prompt-evolution.md`).
- Paths outside the allowlist (e.g. `.env`, `mcp-server/`) are kept by each target.
- `--dry-run` is a reserved npm flag — prefer `npm run sync:dry`.
- **Rollback (A-05):** each real sync snapshots the to-be-changed files into
  `<target>/.kit-backup/<timestamp>/` (last 3 kept). `sync:rollback --target <t>` restores
  the latest (`--snapshot <name>` to pick one, `--list` to see them).

## Release / changelog (C-04)

```bash
npm run release:dry   # preview the next CHANGELOG section from conventional commits
npm run release       # prepend it to CHANGELOG.md (version = PROMPT_VERSION)
npm run git-hooks:install   # enforce Conventional Commits on commit-msg (opt-in)
```

## npm script surface (kit)

| Script | Purpose |
|--------|---------|
| `npm test` | Full deterministic suite (`test:kit`). |
| `npm run lint:feature` | Convention gate. |
| `npm run eval:feature` / `eval:ab` | Score one / A/B two prompt versions. |
| `npm run corpus:add` / `list` / `validate` | Golden-case management (A-02). |
| `npm run verify:browser` | Playwright UI verification. |
| `npm run sync` / `sync:dry` | Push to target repos. |
| `npm run workflow:kpis` / `dashboard` | KPI reports. |
| `npm run workflow:login` | Obtain a `KIT_TOKEN`. |
