# P17-004 A2B: Spec-IR Composition and B0 Convergence

Status: approved implementation plan for the local A2B slice. This plan is stacked on the qualified P17-004 A2A evidence commit `428498ba5a2cd2802c6afb8c48648d134443fc18` and does not authorize remote publication, sync, target edits, provider live I/O, credentials, a version bump, or plugin packaging.

## Decision lock

`migration=M1, authority=A1, bridge=B1, confluence=C1, local=L1, staging=S1, privacy=P1, language=T1, scope=N1`

- **M1 — atomic schema migration:** all built-in adapter descriptors and results move from `1.0.0` to `1.1.0` together. Mixed generations fail closed.
- **A1 — one SpecIR authority:** `packages/core/src/spec-ir.ts` becomes the canonical implementation. The legacy integration path is a compatibility re-export and the target-facing core path is a generated byte-identical mirror.
- **B1 — pure offline bridge:** `packages/core/src/spec-adapter-spec-ir.ts` validates an already parsed `SpecIR` and returns `SpecAdapterResult`; it never reparses source bytes or performs filesystem/network I/O.
- **C1 — Confluence provenance:** B0 canonicalizes staged Confluence input to `sourceKind=confluence` and `sourceRef=confluence:<page-id>` before writing either artifact.
- **L1 — local provenance:** local `.md`, `.txt`, `.docx`, `.pdf`, and `.xlsx` inputs retain format-specific source kinds and use `local:<kind>:<sha256>` as the opaque source reference. Absolute or relative host paths never enter the result.
- **S1 — dual B0 artifacts:** B0 retains `.incoming-spec.ir.json`, adds `.incoming-spec.adapter-result.json`, and B1 consumes the adapter result's `source` object.
- **P1 — warning privacy:** legacy parser warnings are represented only by the unsupported field name `warnings`; warning text is not copied into the provider-neutral result.
- **T1 — TypeScript stays authoritative:** no demonstrated capability or performance gap justifies a Rust, Go, or Python rewrite in this slice.
- **N1 — bounded scope:** provider bundles, live APIs, credentials, sync, target repositories, dashboard changes, publication, and versioning remain out of scope.

## Contract migration

`SpecAdapterDescriptor` version `1.1.0` adds a sorted, unique `sourceKinds` list. JSON-provider descriptors use exactly their provider id plus `utf8-json` and the closed `base-url`/`field-mapping` configuration pair. The SpecIR descriptor uses `spec-ir-v1`, an empty configuration-key list, and the source kinds `confluence`, `excel`, `pdf`, `raw-us`, and `word`.

`SpecAdapterResult` version `1.1.0` accepts either the existing JSON transport or the new `spec-ir-v1` transport. `unsupportedFields` may be empty, remains sorted and unique, and continues to expose names only. Runtime validation and `docs/schemas/spec-adapter-result.schema.json` must reject cross-generation and mixed-shape data.

## Runtime flow

1. Existing intake parses source bytes once and produces canonical `SpecIR`.
2. The offline SpecIR bridge validates the object graph, bounds, provenance envelope, semantic identity, and warning projection.
3. The thin integration composer handles only filesystem/CLI concerns and emits one JSON result on stdout; failures use closed diagnostic labels on stderr.
4. Confluence B0 writes both the compatibility IR and provider-neutral adapter result.
5. B1 reads `adapterResult.source`, preserving the existing semantic-source contract and hashes.

No network request, token, provider SDK, environment lookup, source reparse, or target write belongs in the core bridge.
