# Amendment Schema

This directory holds structured improvement proposals generated by `improve-trigger.ts`.
Each `.md` file is one amendment: YAML frontmatter + prose body.

---

## File Format

```
---
id: AME-YYYY-MM-DD-NNN
triggered_by: [pattern_id_1, pattern_id_2]
pattern_id: manual_correction_spike
pattern_count: 4
pattern_frequency: 0.50
evidence_features: ["FeatureA @ 2026-01-01", "FeatureB @ 2026-01-02"]
risk: low
action_type: prompt_patch
target_section: "B5 + B10 — Spec clarity + agent brief"
status: proposed
proposed_at: 2026-06-11
verify_after_n_runs: 5
pre_amendment_frequency: 0.50
pre_amendment_total_runs: 8
---

## Amendment: <pattern_id>
...prose...
```

---

## Status Lifecycle

```
proposed ──► approved ──► applied ──► verified
    │            │            │
    │            └── (skip)   └── ineffective
    └── rolled_back
```

| Status | Who sets it | Meaning |
|--------|-------------|---------|
| `proposed` | `improve-trigger.ts` | Threshold met; human review needed (high-risk) or auto-apply at B0 (low-risk) |
| `approved` | Human | High-risk amendment reviewed and approved for auto-application |
| `applied` | Workflow agent (B0) | Amendment was applied in a feature run. Log: `applied_at_run: N` |
| `verified` | `improve-trigger.ts` | Pattern frequency dropped ≥30% relative to baseline after N runs |
| `ineffective` | `improve-trigger.ts` | N+2 runs passed without ≥30% drop; amendment did not help |
| `rolled_back` | Human | Amendment reverted (e.g., caused regressions) |

---

## Risk Levels

| Risk | Threshold | Auto-apply? |
|------|-----------|-------------|
| `low` | count ≥ 3, freq ≥ 40%, ≥2 distinct features | Yes — SESSION BOOTSTRAP reads and applies automatically |
| `high` | count ≥ 2, freq ≥ 30% | No — requires `status: approved` before auto-application |

---

## SESSION BOOTSTRAP Step 0.C

At the start of every feature run (B0), the workflow model should:

1. Run: `npx tsx .claude/integrations/improve-trigger.ts --bootstrap`
2. Read the printed amendments (those with `status: approved` OR `status: proposed` AND `risk: low`)
3. For each amendment, apply the described behavior change as a B0 constraint
4. Log the applied amendment IDs to `recovery.log` before proceeding to B1

**Safety constraints:**
- Max one auto-applied amendment per run (apply the highest-frequency one if multiple qualify)
- Auto-amendments can only ADD constraints (strengthen gates, add checks), never remove them
- If a conflict is detected (two amendments target the same section), prefer the most recently proposed

> Status: **wired.** `feature-from-confluence.md` SESSION BOOTSTRAP **Step 0.C — Amendment advisory**
> implements this: it runs `--bootstrap`, applies ≤1 `prompt_patch` amendment as a soft constraint,
> records it with `--mark-applied <AME-ID>`, and logs the applied ID. The behavior is intentionally
> *advisory* (a per-run soft constraint), not a new hard gate — see Step 0.C for the exact safety rules.

---

## Dead-man Switch

If 10+ amendments have status `ineffective`, `improve-trigger.ts` halts all auto-proposals and
prints a warning. This indicates that the trigger thresholds or proposal logic needs human review.
Clear the switch by: setting ineffective amendments to `rolled_back` + reviewing why they failed.

## Commands

```bash
npx tsx .claude/integrations/improve-trigger.ts --status      # print all amendments (incl. archived)
npx tsx .claude/integrations/improve-trigger.ts --bootstrap   # print applicable for B0
npx tsx .claude/integrations/improve-trigger.ts --dry-run     # simulate without writing
npx tsx .claude/integrations/improve-trigger.ts --mark-applied <AME-ID>  # mark as applied (SESSION BOOTSTRAP calls this)
npm run check:amendments                                       # alias for --status
```

## Archive

When an amendment transitions to `verified` or `ineffective`, it is automatically moved to
`docs/specs/.amendments/archive/`. Active commands (`--bootstrap`, decision loop) only look at
the live directory. `--status` shows both active and archived amendments.

## Regression Detection

If a `patternId` already has a `verified` entry in the archive and the same pattern re-triggers,
the new amendment is automatically tagged `regression: true` and its risk is forced to `high`
regardless of the normal threshold classification. This ensures re-emergent patterns receive
human review before auto-application.
